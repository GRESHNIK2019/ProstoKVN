## Интерфейс

- **Подключение**: сервер, отклик, подключение и текущий статус. Ссылка «Маршрутизация» открывает настройки трафика.
- **Подписки**: добавление HTTPS-подписок и VLESS-ссылок, обновление и выбор источников серверов.
- **Маршрутизация**: режим, охват TUN / системный прокси, отдельные списки сайтов и приложений. По умолчанию видны свои правила; автоматические доступны через фильтр.
- **Настройки**: дополнительные параметры TUN и обновления клиента.
- **Диагностика**: проверка маршрутов, сведения о соединении и журнал.

Сайты сгруппированы по сервисам; IP и подсети находятся в отдельных группах. Группы и адреса отсортированы. Свёрнутые группы сохраняют своё состояние при обновлении списка, поиск раскрывает подходящую группу.

Редактор правила открывается поверх списка. Можно вставить домен, HTTP(S)-ссылку, IP или CIDR; для приложения — имя процесса или полный путь к `.exe`. Для домена выбирается весь домен с поддоменами либо точный адрес. Название и отдельный сервер находятся в дополнительных параметрах. Escape закрывает редактор без сохранения.

## Работа в трее

Крестик и Alt+F4 скрывают окно в трей, сохраняя VPN-подключение. Двойной щелчок по значку или пункт **Открыть ProstoKVN** в меню правой кнопки возвращает окно. Для завершения клиента выберите **Выход** в этом меню: приложение дождётся операции подключения и выполнит штатную очистку. Кнопка **Отключиться** на главной останавливает VPN без завершения клиента.

## Раздельная маршрутизация

1. В разделе **Маршрутизация** выберите **Только выбранное**.
2. Добавьте нужные сайты / приложения и выберите VPN, напрямую или блокировку.
3. Оставьте включённым переключатель **Включить в режим «Только выбранное»** для нужных правил.
4. Подключитесь. Если уже подключены и меняли режим или параметры сети, нажмите **Применить**.

В этом режиме используется TUN; запуск от имени администратора обязателен. Весь остальной трафик идёт напрямую. Скрытых правил VPN для Discord, Telegram и AI-сервисов в раздельном режиме нет. Старые ручные правила включены по умолчанию; автоматически созданные правила требуют явного включения.

Обычные изменения правил применяются без перезапуска ядра. Если изменение требует новой структуры конфигурации, клиент показывает необходимость переподключения. Ошибка применения видна на странице; сохранение на диск не выдаётся за успешное применение. После удаления или изменения правила подходящие старые соединения закрываются, чтобы приложения открыли их с новым маршрутом.

Приоритет: служебные подключения и локальная IPv4-сеть → ваши собственные ручные правила (путь приложения, имя процесса, IP / подсеть, домен с учётом точности) → явные наборы правил → разрешённые режимом автоматические правила → маршрут по умолчанию.

В интерфейсе ровно три режима:

- **Весь трафик**: VPN по умолчанию с ручными исключениями.
- **Только выбранное**: только включённые вами сайты и приложения; по умолчанию напрямую.
- **Умный**: ручные правила, встроенные маршруты Discord / Telegram / AI и проверяемое обучение; по умолчанию напрямую.

Старый **Правила + Discord** автоматически переносится в **Только выбранное**. Discord появляется как видимый набор правил приложений, который можно изменить или удалить. Существующие ручные исключения сохраняют приоритет над набором, в том числе исключения для сайтов внутри Discord. Правила, явно изменённые через редактор, становятся обычными ручными правилами.

Старый **Без VPN** переносится в **Только выбранное** с выключенными правилами: трафик остаётся прямым. Для завершения клиента используйте **Выход** в трее; **Отключиться** останавливает VPN. В режиме **Только выбранное** нужен TUN и запуск от имени администратора.

Перед переносом клиент создаёт парную резервную копию `settings.json` и `routes.json` в папке `routing-modes-backup-*` внутри каталога данных. Повторный запуск не создаёт дубликатов правил или новых копий после успешного переноса. Режимы выбираются и сохраняются по стабильным идентификаторам, независимо от порядка пунктов меню.

Системный прокси охватывает только использующие его приложения. Для игр, UDP и перехвата трафика приложений нужен TUN. DNS через HTTPS и уже открытые соединения могут влиять на сопоставление доменных правил. Клиент не измеряет реальные потери UDP голосового канала.

## Сборка и проверки

```powershell
dotnet build .\SmokeTest\SmokeTest.csproj
$env:PROSTOKVN_TEST_HOME = Join-Path $PWD 'artifacts\routing-check'
$env:PROSTOKVN_ROUTING_REFACTOR_TEST = '1'
.\SmokeTest\bin\Debug\net10.0-windows\win-x64\SmokeTest.exe
```

Для тестов с Mihomo поместите `mihomo.exe` в `core` рядом с `SmokeTest.exe`. Набор проверяет политику всех режимов, приоритеты, исключённые и просроченные правила, удаление правил у открытых соединений, имена серверов с запятыми, обновления через API отдельного Mihomo и интерфейс в обеих темах. Отдельное тестовое ядро использует свободный порт контроллера и не включает TUN или системный прокси.

Проверка трёх режимов и переноса старых настроек: `PROSTOKVN_THREE_ROUTING_MODES_TEST=1` (также нужен отдельный `PROSTOKVN_TEST_HOME`). Она сравнивает маршруты до и после переноса, проверяет приоритеты, повторный запуск, резервные копии, откат при ошибке записи и интерфейс.

Проверка группировки, поиска и трея: `PROSTOKVN_CLIENT_SHELL_TEST=1` с отдельным `PROSTOKVN_TEST_HOME`.

Исходники маршрутизации: `ProstoKVN/RoutingPolicy.cs`, `HotRuleProviders.cs`, `VpnCore.cs`. Интерфейс правил: `MainWindow.Routing.cs` и `MainWindow.xaml`.

Настройки находятся в `%LOCALAPPDATA%\ProstoKVN`; старые данные `%LOCALAPPDATA%\VEGA VPN` импортируются без перезаписи новых настроек. URL подписок защищены DPAPI текущего пользователя Windows. `config.yaml` и файлы sidecar могут содержать данные подключения — не публикуйте их.
