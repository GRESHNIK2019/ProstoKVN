# ProstoKVN 0.33.3 — подписки Remnawave и нативные JSON-транспорты

- Добавлен ответ на HWID-запрос провайдера: клиент отправляет постоянный идентификатор этого Windows-пользователя и общие сведения о платформе. Исходные MachineGuid и SID не передаются; идентификатор вычисляется с отдельным префиксом ProstoKVN. Обновление версии не создаёт новое устройство.
- Идентификатор отправляется только после явного HWID-запроса сервера и повторно используется при обновлении подписки. Перенаправления на другой адрес не выполняются автоматически.
- Для подходящих HWID-подписок клиент автоматически запрашивает нативный `/json`, сохраняя собственный User-Agent ProstoKVN и один идентификатор устройства. При отсутствии этого формата используется доступный основной ответ.
- Ответы «App not supported», «Превышен лимит устройств» и служебные заглушки показываются как ошибки провайдера. Они не добавляются в список серверов и не заменяют рабочий кэш. Лимит устройств не обходится.
- Нативные Trojan gRPC/TLS и Xray Hysteria2 направляются через Xray с исходными параметрами TLS, аутентификации, gRPC, QUIC и Salamander/FinalMask. Существующие Hysteria2 share-ссылки продолжают использовать sing-box.
- VLESS XHTTP/REALITY сохраняет исходную конфигурацию транспорта. Чужие входящие слушатели, DNS и правила маршрутизации из подписки не запускаются.
- Xray получил собственное разрешение адресов VPN-серверов через DoH с IP-адресами начальных DNS-серверов. Это позволяет избегать адресов Fake-IP, выданных работающим TUN. Проверка сертификатов сохраняется.
- Именованные нативные профили и варианты транспорта сохраняются при удалении дубликатов и объединении подписок. Для проверенной подписки импортируются все 41 профиля.
- Сохранены лимит 100 серверов на ссылку, увеличенное окно и исправление количества групп правил из предыдущих версий.

Проверено: загрузка реальной подписки после освобождения слота устройства, импорт и объединение всех 41 профиля, зашифрованный кэш, проверка всех нативных конфигураций настоящим Xray и конфигурации маршрутизатора Mihomo для VLESS, Trojan и Hysteria2. HTTPS-трафик через VLESS XHTTP и Trojan gRPC проверен на отдельных локальных SOCKS-портах без изменения системного прокси и TUN.

При проверке Hysteria2 конфигурации приняты ядром, но UDP-соединение с выбранными серверами завершилось таймаутом. Фактическое подключение Hysteria2 в текущей сети не подтверждено.

Справка для разработчиков: [HWID Remnawave](https://docs.rw/features/hwid-device-limit/), [Hysteria в Xray](https://xtls.github.io/en/config/outbounds/hysteria.html).
